# 多主体与框架合同需求书

日期：2026-10-19（第三稿：三件事合成一份，供一次开发）  
状态：待确认。确认前不改代码。  
基线：现行源码（含报销/折旧/退货的主体收紧，以及迁移 `2026-10-19-fix20-contract-scope-and-fks.sql`）

本文件取代前两稿里互相打架的句子。开发时只看这一份。

三件事一起做：

1. 多家我方主体并行。签约和收入跟合同主体；采购、人工成本、房租等开支可以自选主体。
2. 框架合同可以不写金额。没有约定总额时，金额按项目实际发生。
3. 一份框架合同下面可以立多个项目。普通合同仍是一份合同一个项目。

## 1. 业务事实

公司同时有多家我方纳税主体。一份合同只由其中一家签署，签在 `erp_contract.tax_entity_id` 上。

计费模式里，`framework` 是框架协议。框架下面会按实际业务不断立项，项目之间金额各自发生，都挂在同一份协议上。

现行代码做不到后半句：

- 表上有唯一索引 `uq_erp_project_one_contract`（同一 `contract_id` 只能有一行项目）。
- 立项时若该合同已有项目，直接返回那个旧项目，不再插入（`projects.service.ts` 约 910–915 行）。

框架下单走 `erp_calloff`。合同头金额为 0 时，下单会被「超过框架上限」拒绝。销项可开金额按「合同头 − 已开销项」计算，头金额为 0 时开票也会被拒绝。

金额分两种，不要混用：

- **约定总额**：合同头 `amount`。大于 0 表示有上限。框架合同头金额为 0 或空，表示还没约定总额，不是这笔业务价值为 0。
- **实际发生**：每个项目自己的预算、收入、成本、开票，以及框架订单。无总额的框架以这些为准。

## 2. 判定

**签约与收入跟合同。** 合同、各项目的收入确认、销项发票、有约定总额时的印花税，主体等于这份合同的签约主体。多家并行时不能改到别的主体，也不能空着落到默认主体。框架下有多个项目时，每个项目的收入和销项仍用这一份合同的主体，不按项目再选签约主体。

**开支可以自选。** 采购、人工成本、房租，以及费用报销、手工项目成本，可以选定我方主体。单据挂了项目时，表单默认带出该项目所属合同的主体，允许改成另一家启用中的主体。凭证以单据上保存的主体为准。

**框架可以没有金额，并且可以有多个项目。** 每个项目自带大于 0 的预算。无总额时不拿合同头去卡下单和开票。有总额时，全部项目加在一起不得超过该总额。

默认主体只在「启用主体恰好一家」时使用。多家并行时，不得用它填空白单据。

已过账凭证不自动改主体。错归只出清单，红冲或作废后重开。

## 3. 已经符合、这次不要重做

| 环节 | 现行行为 |
|---|---|
| 合同提交、审批 | 没有 `tax_entity_id` 则 400，「请先选择纳税主体」 |
| 头金额为 0 且没有明细 | 提交校验放行 |
| 印花税 | 有主体才计提，并传入该主体 |
| 无项目费用、无项目资产 | 多家时必须自选主体 |
| 报销、折旧、采购退货、销售退货 | 多家且推不出主体时不出凭证，补偿原因「未归属纳税主体」 |
| 合同结项回写 | 同一合同下的项目要全部 `closed` 才把合同改成 `completed`。有未结项或已取消的项目则不回写 |

有项目的报销今天强制等于合同主体。这次改为可自选，不要保持旧行为。

「一合同只能有一个项目」今天由唯一索引和立项时的提前返回共同保证。这次只对框架合同放开，普通合同继续只能有一个项目。

## 4. 还不符合

| 环节 | 现状 |
|---|---|
| 新建合同 | 主体可空，会被写成默认主体 |
| 合同主体 | 离开草稿后仍可改 |
| 有项目的报销 | 强制合同主体 |
| 人工成本、手工项目成本 | 不能自选主体；没有合同主体时落到默认主体 |
| 采购、进项、应付 | 不能自选，按合同或供应商上的我方主体猜测 |
| 房租 | 没有我方主体字段 |
| 框架立项 | 第二份项目插不进去，接口返回已有的那一个 |
| 框架头金额为 0 | 下单、开票都被合同头 0 拦住 |
| 框架生效 | 可能按 0 元去计提印花税 |
| 凭证兜底 | 成本、收入、发票、工资等在多家时仍会落到唯一的默认主体 |
| 收入、销项 | 合同没主体时，解析仍可能填上默认主体 |

`md_supplier.tax_entity_id` 是我方归属，不是对方税号。采购单没有自选主体时才用它。为空时不得因此写成默认主体。

## 5. 规则

「多家」指 `status = 'active'` 的纳税主体多于 1 个。「一家」指恰好 1 个。不要用默认标记的个数来判断。

### 5.1 签约与收入

| 单据 | 规则 |
|---|---|
| 合同 | 多家时创建必填主体。未选择不得写入默认主体 |
| 收入确认 | 主体等于所挂合同。项目上确认收入时，用该项目的 `contract_id` 找到的那份合同。多家且合同没主体：不插入收入凭证 |
| 销项发票 | 主体必须等于所挂合同，改成其他主体返回 400。可开额度见 5.4 |
| 印花税 | 约定总额大于 0 时，生效按合同主体计提。框架头金额为 0：生效时不计提 |

框架下每一个项目的收入和销项都用同一签约主体。一家时，合同提交仍须已有主体。下游完全没传主体时，可以用那一个启用主体。

### 5.2 开支可以自选

范围：采购订单、进项发票、应付、人工成本（工时确认生成的成本）、手工项目成本、费用申请与报销、行政房租。

1. 单据保存我方主体。挂了项目或合同时，打开表单默认带出该合同主体，允许改成其他启用主体。
2. 凭证显式使用单据上的主体。
3. 多家、用户清空、又没有合同可带出：创建 400，「请选择我方纳税主体」。
4. 一家且留空：用那一个启用主体。
5. 有项目的报销允许与合同主体不同。

`erp_project_cost`、采购订单、房租账单增加可空 `tax_entity_id`。列可空，便于一家时的历史行迁入。多家必填在服务层判断。工时确认和手工成本写入成本行的这一列。

进项发票、应付若从采购单带出，带出采购单主体，允许在发票或应付上再改。凭证以最后保存的那张单为准。退货沿用原单主体。

### 5.3 没有合同也没有自选

| 单据 | 多家 | 一家 |
|---|---|---|
| 无项目报销、无项目资产 | 必填 | 可空，用那一个启用主体 |
| 工资计提 | 工资单必填，否则审批 400 | 可空，用那一个启用主体 |
| 手工凭证 | 必填 | 可空，用那一个启用主体 |

工资不按员工或部门推断。

### 5.4 框架合同

只在 `billing_model = framework` 时适用。项目、按量、订阅不获得这些例外。

**多个项目**

- 同一框架合同可以创建任意多个项目。每次立项都插入新项目，不得因为已有项目就返回旧项目。
- 去掉 `uq_erp_project_one_contract`。普通合同改由服务层拒绝第二份项目，文案「该合同已立项」。
- 每个项目的预算单独填写，必须大于 0。框架头净额为 0 时，不允许用合同净额充当项目预算。
- 全部项目都 `closed` 之后，才把框架合同回写成 `completed`。存在未结项或已取消的项目时不回写。这条与今天的结项逻辑一致，多项目后继续用它。
- 项目不另存签约主体。收入和销项读所属框架合同的主体。

**头金额为 0 或空**

- 表示没有约定总额。
- 创建时不自动补 0 元明细。提交、审批不要求明细。
- 下单不与合同头比较。
- 销项不按合同头算可开金额。某一项目的可开金额 = 该项目已确认收入合计 − 该项目已开且未作废的销项。该项目还没有已确认收入时，开票 400，「该项目尚无已确认收入」。合同下其他项目的收入不能挪来开这一项目的票。
- 收入金额按各项目实际确认，不与合同头 0 比较。
- 生效时不插入印花税凭证。不对订单补计印花税，那是以后的需求。

**头金额大于 0**

- 表示有框架上限。
- 全部订单累计不得超过该上限。
- 全部项目的销项合计不得超过该上限。单个项目仍不得超过自己的已确认收入。
- 生效时按合同头金额和签约主体计提印花税。

普通合同头金额为 0 时，仍只是「可以没有明细就提交」，不能无上限下单，也不能立第二个项目。头金额大于 0 的普通合同，明细合计与头金额一致后才能提交。

框架头金额为 0 仍然必须有签约主体。

### 5.5 合同主体锁定

草稿可以改签约主体。提交之后不能再改 `taxEntityId`。要换主体，终止这份合同，另签一份。已立项的多个项目都跟着原主体，不随头表改写。

开支单据上另选的主体不受这把锁影响。

### 5.6 凭证解析

显式传入优先。开支自选主体靠这一级生效。

其次才从单据走到合同。用于收入、销项，以及开支单据自己没保存主体的历史数据。

第 ③ 级：

- 启用主体等于 1：用这一个。
- 大于 1：所有来源类型都返回空，不再查默认主体。
- 等于 0：返回空。

空则不插入无主体凭证，也不插入默认主体。补偿原因「未归属纳税主体」。

税率解析在多家、且没有传入主体、客户和供应商上也没有我方主体时，返回空。新建合同、销项、收入确认得到空则 400，「请选择我方纳税主体」。

## 6. 历史数据

先补仍有效合同的签约主体，再改规则。不把默认主体批量改成另一家。已过账凭证只红冲或作废重开。

新的主体列上线后，历史成本、采购、房租的主体留空。一家时再次出凭证可用那一个启用主体。多家时能从所挂合同带出就带出；带不出则进补偿队列。不要求上线前逐笔补历史人工成本。

已有数据里每个合同最多一个项目，删掉唯一索引不会撞车。

```sql
SELECT count(*) FILTER (WHERE status = 'active') AS active_entities,
       count(*) FILTER (WHERE status = 'active' AND is_default = 1) AS default_active
FROM md_tax_entity;

SELECT id, code, name, status, billing_model, amount
FROM erp_contract
WHERE tax_entity_id IS NULL
  AND coalesce(status, '') NOT IN ('void', 'terminated');

SELECT id, code, billing_model, amount, status
FROM erp_contract
WHERE billing_model = 'framework'
  AND coalesce(amount, 0) = 0
  AND coalesce(status, '') NOT IN ('void', 'terminated');

SELECT contract_id, count(*) AS project_count
FROM erp_project
WHERE contract_id IS NOT NULL
GROUP BY contract_id
HAVING count(*) > 1;

SELECT id, code, source_type, source_ref, status, period
FROM fin_voucher
WHERE tax_entity_id IS NULL
  AND coalesce(status, '') <> 'voided';
```

框架且头金额为 0 的清单只核对，不自动改金额，不自动补项目。`project_count > 1` 在删索引之前应为 0 行。若已有行，先人工处理再删索引。

## 7. 验收

多家，两个启用主体，只有一个标为默认（下称 B）：

- 新建合同不传主体返回 400。传入 A 则保存为 A。
- 离开草稿后修改主体返回 400，原值不变。
- 合同主体为 A 的项目，确认收入、开销项：凭证为 A。销项改成 B 返回 400。
- 该项目的人工成本或报销默认 A，改成 B 后凭证为 B。
- 采购订单默认 A，改成 B 后，进项凭证为 B。
- 房租不选主体返回 400。选 B 则凭证为 B。
- 不产生「没人选却落到 B」的凭证。

框架合同，头金额 0，主体 A：

- 无明细可以提交、审批。
- 连续立项三个项目均成功，三个 `contract_id` 都是这份合同，预算各自独立且都大于 0。不填预算返回 400。
- 下单 10 万、再下单 5 万都成功。
- 某项目没有已确认收入时，按该项目开销项返回 400。该项目确认收入 8 万后，这个项目最多开 8 万。另一项目已确认的收入不能用来开这一张。
- 生效时没有印花税凭证。
- 三个项目都结项后，合同变为 `completed`。只结项两个时，合同状态不变。

框架合同，头金额 100 万，主体 A：

- 可以立多个项目。
- 订单累计超过 100 万返回 400。
- 各项目销项合计超过 100 万返回 400。
- 生效时按 100 万和主体 A 计提印花税。

普通合同：

- 已有一个项目时再立项返回 400，「该合同已立项」，不返回旧项目冒充新建成功。
- 头金额大于 0 时，明细合计不一致不能提交。

一家时：留空的无项目报销、房租、人工成本仍能保存，凭证等于那一个启用主体。框架多项目、头金额为 0 的开票规则不变。

## 8. 不做

- 不批量改已过账凭证的主体。
- 不把客户档案上的主体自动写成合同主体。起草可以带出，多家下保存前必须确认。
- 不让普通合同拥有多个项目。
- 不按员工或部门拆工资。
- 不改印花税税目和税率。只规定头金额为 0 的框架在生效时不计一笔。
- 不调整小规模 1% 征收率、差额征税、跨主体视同销售。

## 9. 开发顺序

确认后一次做完，按这个顺序：

1. 财务补完仍有效合同的签约主体。核对框架头金额为 0 的清单。确认没有合同已经挂了两个项目。
2. 删掉 `uq_erp_project_one_contract`。框架立项改为总是新建；普通合同第二份项目返回 400。每个新项目预算必填且大于 0。结项回写仍等全部项目结项。
3. 框架头金额为 0：取消下单上限；销项按单个项目的已确认收入封顶；生效不计印花税。头金额大于 0：订单累计和全部销项合计都不得超过头金额。
4. 合同多家创建必填主体，离开草稿后锁定。
5. 人工成本、采购、房租、报销增加可选主体，默认带出合同主体。凭证显式使用单据主体。
6. 税率解析和凭证第 ③ 级在多家时不再返回默认主体。
7. 按第 7 节做测试。历史已过账错归只留清单。
