# 晟笙 ERP 前端 UI 设计需求书

> 说明放在哪，以《前端UI设计需求书-v3.2-逐项说明》为准。本文第 5 节「整页只有一个说明」不再采用。  
> 状态：设计需求，不改代码  
> 日期：2026-10-19  
> 替代关系：v2.1 里「操作组末尾单独一个 ?」不再采用。表格列优先级、一页一个主操作、Quiet Ledger 的低饱和视觉，继续沿用。

---

## 1. 要解决的问题

当前界面把「怎么填」和「填了会怎样」写在控件旁边或控件下面。结果是表单变长、字变小、主任务被说明挤开。

纳税主体弹窗是典型画面（见本次截图红框）：

- 「小型微利企业资格」下拉本身已经写了「未确认（按不享受处理，偏严）」。
- 下拉下面再铺一整段：「三个条件须**同时**满足且需人工确认……」。
- 城建税率、申报周期下面也各有一段灰色说明。
- 星号是写给人看的强调，界面按纯文本渲染，用户看到的是 `**同时**`、`**拒绝出数**`。
- 选项文案把法规条件塞进下拉项，一项能占两行。

另一类问题是字段标签旁的 `i` / `?`：

- 视觉大约 14px，点按区域大约 24px，和标签挤在一行。
- 一屏出现多个，用户不知道该点哪一个，也容易把口径说明当成必读正文。
- 操作组末尾的 `?` 又经常被推到页面最右侧，和它要解释的按钮分开。

全站还有这些已经核对过的结构性问题，本需求一并收口：

- 列表操作位置不统一：有的在页头，有的在筛选条，有的在 Tab 下。
- 行内按钮过多，操作列盖住业务列。
- 同一页同时出现说明条、黄条、红条。
- 表格外框有的套卡片、有的裸表。
- 复杂表单和 3 个字段的确认框用同一宽度的弹窗。

## 2. 目标

做完之后，一个不熟悉税务口径的财务人员应当能够：

1. 打开任一列表，在 3 秒内找到唯一主操作，并完成搜索或筛选。
2. 打开任一表单，先看到要填的字段，不被说明段落打断。
3. 需要理解口径时，只去一个地方：这一页或这一弹窗右上角的「说明」。
4. 需要理解某个不直观的按钮时，只去这个按钮右上角的说明标记。
5. 在 1280 和 1440 宽度下，核心列都能看见，危险操作都有明确后果。

四个质量词的可检查定义：

| 词 | 可检查标准 |
|---|---|
| 简洁 | 表单字段下没有说明段落。一页最多一条持续提示。一屏帮助入口不超过「1 个页面说明 + 需要解释的按钮各 1 个标记」。 |
| 易懂 | 字段名、选项、按钮都是短词。法规、计算、偏严口径放在说明里，用完整句子。界面不出现 Markdown 符号。 |
| 易操作 | 主操作始终在标题行右侧。保存、取消在表单底部右侧。危险操作二次确认。帮助标记的点按区域不小于 28×28。 |
| 美观 | 同一套字号、颜色、圆角、间距。内容区无投影。状态只用颜色表达状态，主色只用在当前操作和当前选中。 |

## 3. 范围

覆盖登录后的全部前端：侧栏、顶栏、列表、详情、表单页、弹窗、抽屉、报表、空态、错误态。

不在本次改变：

- 业务计算规则、权限、接口字段。
- 纳税主体「未确认按不享受」「未配置城建税拒绝出数」等口径本身。只改变这些口径在界面上的呈现位置和写法。

## 4. 设计原则

1. **先任务，后说明。** 默认界面只服务「填完并保存」或「找到并处理」。说明按需打开。
2. **说明只有两个锚点。** 页面或弹窗的右上角；需要解释的那个按钮的右上角。不再在字段标签旁放 `i`。
3. **控件表达当前值，说明表达规则。** 下拉显示「未确认 / 符合 / 不符合」。为什么未确认会按 25% 计，写在右上角说明里。
4. **当前选择若会导致多缴或无法出数，字段下保留一句状态，不保留一段教程。** 这句是结果，不是帮助文档。
5. **一页一个主按钮。** 蓝色只给这一个。其余为线框或文字按钮，多余的收进「更多」。
6. **同一类页面长得一样。** 列表、详情、单据、设置、报表各用一套模板，不按模块各自发明页头。

## 5. 帮助系统

这是本次的主决策。

### 5.1 页面说明

位置：页面标题行的最右侧。顺序从左到右为：

```text
页面标题                         [ 主操作 ]  [ 次操作 ]  [ 更多 ]  （说明）
```

「说明」在全部按钮的右边，贴近页面内容区的右上角。它解释的是这一页，不是某一个按钮。

弹窗同样处理。标题行右侧、关闭按钮左边：

```text
新建纳税主体                              （说明）    ×
```

说明与关闭按钮间距 8px。关闭仍然是最右。没有口径需要解释的弹窗不放说明，例如「确定删除这条记录？」这种确认框，后果直接写在正文里。

打开方式：点击。不使用悬停作为唯一入口，避免鼠标划过时挡住表单。键盘 Enter / Space 打开，Esc 关闭。

打开后的容器：

| 场景 | 容器 | 宽度 |
|---|---|---|
| 列表页、详情页、报表页 | 从右侧滑出的说明抽屉 | 360px |
| 弹窗、不超过 6 个要点的短说明 | 标题下方对齐到右侧的浮层 | 320px |
| 超过 6 个要点，或含分节 | 说明抽屉，盖在弹窗之上 | 360px |

内容结构固定：

```text
这一页在做什么
一句，不超过 28 字。

需要知道的口径
· 标题
  两到三句。先写结果，再写原因。

不影响操作的延伸阅读
查看说明 →     仅当已有文档时出现
```

规则：

- 一个页面、一个弹窗只有这一个说明入口。
- 字段级口径全部收进这份说明，按字段或按决策分节，用户不用在表单里找。
- 每节先写「选了会怎样」，再写「为什么系统不能自动判断」。
- 不在说明里重复按钮名称列表。按钮自己的右上角标记负责按钮。

### 5.2 按钮说明

只放在「看名字无法判断后果或前置条件」的按钮上。标记在该按钮边框的右上角，压住按钮圆角，不漂到按钮外面很远。

```text
        （i）
   ┌──────────────┐
   │  确认底稿     │
   └──────────────┘
```

规格：

| 项 | 要求 |
|---|---|
| 图形 | 16px 线框圆圈，内为 `i`，线宽与全站图标一致 |
| 位置 | 相对按钮右上角外扩 6px，视觉上属于这个按钮 |
| 点按区域 | 28×28，大于图形本身 |
| 默认色 | 次要文字色，白底圆，1px 浅边框，避免和主按钮蓝糊在一起 |
| 悬停 | 图形变为正文色，圆底变为浅灰 |
| 打开 | 点击后在按钮下方右对齐打开 320px 浮层 |
| 数量 | 一个按钮最多一个标记。一屏这类标记建议不超过 3 个 |

必须带标记的操作：

- 同步到外部系统、覆盖导入
- 提交审批、撤回审批
- 确认底稿、结转、反结转、年结
- 作废、红冲、终止、处置、减值
- 数据授权、脱敏导出

不带标记的操作：

- 保存、取消、关闭
- 新建、编辑、查看
- 搜索、筛选、导出当前列表
- 删除类操作：不靠标记解释，确认框正文写清对象和后果

浮层只回答三件事，能省则省：

1. 点下去会发生什么。
2. 什么情况下点不了，或点了不会生效。
3. 能否撤销。

不超过 4 行。更长的规则回到页面说明。

### 5.3 字段下允许留下的唯一一种句子

当且仅当当前值会导致「多缴、无法出数、不会自动判断」时，在控件下显示一句状态。值一旦改成明确选项，这句话消失或改成对应结果。

允许：

```text
未确认：按 25% 计税，可能多缴。
未填写：增值税附加税无法出数。
```

不允许：

```text
三个条件须同时满足且需人工确认：从业人数与资产总额本系统没有取数能力，
故不做自动判定。未确认时按不享受处理（多缴而非少缴）；应纳税所得额超过
300 万时即使选「符合」也会自动降为 25%。
```

这段放进弹窗右上角说明的「小型微利企业资格」一节。

校验错误仍然留在字段下，用危险色，一次只指出这一项怎么改。

### 5.4 不再使用的呈现

- 字段标签右侧的 `FieldHelp` 小图标。
- 操作组末尾、与按钮脱离的独立 `?`。
- 字段下的多句灰色说明。
- 把政策写进 placeholder。placeholder 只给格式例子，例如 `7、5 或 1`。
- 把政策写进下拉选项。选项只保留短标签；长条件进说明。
- 同一页堆叠多条说明条。持续可见的提示条全页最多一条，并且只用于「不处理就不能继续」。

## 6. 视觉基线

方向维持安静的账本：白底、细线、少色、无装饰渐变。

### 6.1 颜色

| 用途 | 值 |
|---|---|
| 页面背景 | `#F6F7F9` |
| 卡片、表格、弹窗 | `#FFFFFF` |
| 主文字 | `#171A20` |
| 次要文字 | `#5F6673` |
| 辅助文字、说明标记 | `#8A91A0` |
| 边框 | `#E7E9EF` |
| 输入框边框 | `#D8DCE6` |
| 主色 | `#3D5AFE` |
| 主色浅底 | `#EEF1FF` |
| 成功 | `#1F9D6A` |
| 警告 | `#C47A12` |
| 危险 | `#D14343` |

主色只出现在主按钮、当前导航、当前选中行、焦点环。状态色只出现在状态。金额不为正负单独发明新颜色，负数用危险色，零和正数用主文字。

### 6.2 字号

全站只用这一套，不再出现 11px 的说明墙和 14px 的字段名混在同一表单里抢层级。

| 角色 | 字号 / 行高 | 字重 |
|---|---|---|
| 页面标题 | 20 / 28 | 600 |
| 弹窗标题 | 16 / 24 | 600 |
| 分区标题 | 13 / 20 | 600 |
| 字段名、表格、按钮 | 13 / 20 | 500（字段名），400（表格正文） |
| 状态句、说明正文 | 12 / 18 | 400 |
| 表头 | 12 / 16 | 500 |

页面标题从现在的 24px 收到 20px。ERP 列表需要把纵向空间让给表格，24px 标题在 1280 高度上挤掉一行数据。

数字、金额、税率、编码使用等宽数字。金额右对齐，保留两位小数，千分位。税率显示为 `6%`，不显示 `6.00%`，除非该字段允许小数税率。

### 6.3 间距、圆角、图标

| 场景 | 值 |
|---|---|
| 页面左右留白 | 24px，宽屏内容最大 1440px 居中 |
| 标题行与内容 | 16px |
| 表单分区之间 | 20px |
| 同分区字段之间 | 16px |
| 标签与控件 | 6px |
| 按钮之间 | 8px |
| 表格单元格左右 | 12px |
| 表格行高 | 44px |

圆角：按钮和输入框 8px，表格容器和卡片 12px，弹窗和抽屉 16px，说明标记为圆形。

内容卡片不加阴影。阴影只给弹窗、抽屉、浮层。图标统一 Lucide，线宽 1.75。导航和按钮 16px。

## 7. 壳层

### 7.1 侧栏

宽度展开 220px，收起 64px。背景白色，右侧 1px 分割线。

分组保持现有任务分组，不按后端模块重排：

- 工作台：经营看板、指标中心
- 客户与合同：客户、线索与商机、合同
- 项目交付：项目、成本、收入确认
- 采购与资产：采购、供应商、退货、固定资产
- 财务：应收应付、票据、预算费控、总账、报表、账簿、税务申报、期末年结
- 人力与行政：人力资源、租房、缴费、行政资产、车辆与差旅
- 企业文档：云空间、知识库
- 底部「系统」默认收起：纳税主体、自动化、审计、数据资产、设置

导航项高度 36px。当前项使用主色浅底和主色文字，左侧 2px 主色条。分组标题 12px、次要色。记住展开状态。1280 以下默认收成图标条，悬停或点击展开浮层，不把内容区压到表格无法阅读。

### 7.2 顶栏

高度 52px。左：侧栏开关和面包屑。中：搜索，占位「搜索客户、合同、项目、凭证」。右：待办、外观、当前用户。

「新建」不放在顶栏。各页的新建是该页主操作，放在该页标题行。顶栏放新建会让用户不知道新建的是哪一类单据。

### 7.3 标题行

每个业务页都使用同一行：

```text
面包屑
标题                          [主操作] [次操作] [更多] （说明）
可选的一行状态，不超过 24 字
```

标题下那一行只写当前范围，例如「当前主体：晟笙科技 · 2026 年 10 月」。不写操作教程。

## 8. 五类页面模板

### 8.1 列表

结构：标题行、最多一条提示条、筛选行、表格、分页。

筛选行从左到右：搜索框、最多 3 个常用筛选、其余收进「筛选」。右侧可放「导出」「列设置」，它们是次操作，不和标题行的主操作重复。

表格：

- 外框 1px、圆角 12px，不再有的页面套卡片、有的页面裸表。
- 首列是编号或名称，可点击进入详情。
- 状态用固定宽度的文字徽章，不用彩色大按钮。
- 金额列右对齐。
- 操作列固定在右，宽度按「两个文字按钮 + 更多」计算，不盖住前一列。列总宽超过容器时横向滚动，表头和操作列保持可见，容器右侧用 16px 渐隐提示还有列。
- 1440 与 1280 都至少保留：识别列（编号、名称）、对象列（客户或供应商）、金额或状态、操作。日期、负责人、备注等进详情或「列设置」。
- 行内可见操作最多两个，且必须是该行最高频的安全操作，例如「查看」「编辑」。作废、删除、认证、转项目放进「更多」。
- 空态：一句原因，一个主操作。例：「还没有纳税主体。合同审批和开票前需要先建一个。」按钮「新建纳税主体」。

分页在表格右下。默认 20 条。

### 8.2 详情

标题行包含单据号和状态徽章。标题下是 4 到 6 个摘要字段，一行排完：对象、金额、负责人、日期、所属主体。

正文用标签页，顺序固定为：概览、明细、关联、附件、日志。没有内容的标签不隐藏，显示空态，避免用户以为功能不存在。

右侧不另做 1/3 信息栏。摘要已经在标题下，再做右栏会在 1280 宽度把明细挤窄。关联对象用概览里的链接。

### 8.3 单据表单

超过 8 个字段，或需要分「基本信息 / 税务 / 结算」时，使用独立页面，不用弹窗。

页面分两列：左侧表单占 8，右侧在宽屏占 4。右侧只放三样：当前状态、未填但会影响出数的项、附件。窄于 1280 时右侧落到表单下面。

底部操作条吸底，高 56px：左侧写「有未保存的修改」或留空，右侧「取消」「保存」。保存是唯一主按钮。

字段：

- 标签在上，必填用主色星号，星号在标签后，不在标签前。
- 同一分区两列。关联紧密的两个字段才并排，例如开始日期和结束日期。
- 错误出现在该字段下，提交时焦点落到第一个错误。
- 离开未保存页面时确认。

### 8.4 弹窗

| 种类 | 宽度 | 用于 |
|---|---|---|
| 确认 | 420px | 删除、作废、终止。标题是动作，正文两句：对象是谁、会发生什么。按钮「取消」和危险色动作名 |
| 短表单 | 560px | 6 个及以下字段，不需要分节 |
| 标准表单 | 720px | 7 到 12 个字段，需要分节。纳税主体新建用这档 |
| 导入预览 | 880px | 列映射和错误行 |

弹窗头部固定，正文滚动，底部操作条固定。不把保存按钮滚出视口。点击遮罩不关闭已填写的表单，避免误触丢稿；确认框可以点遮罩关闭。

### 8.5 报表与账簿

保留表格的全部列，允许横向滚动，但必须同时满足：

- 首列冻结。
- 滚动条出现在表格底部，不藏进行高内部。
- 表格上方有一行范围：主体、期间、是否包含未过账。改变范围的控件和这行在一起。
- 导出在标题行，作为次操作。
- 口径差异不写在每个数字下面，收进页面右上角说明。某个数字因缺配置无法计算时，单元格显示「—」，悬停或点击该单元格给出一句原因，并链到页面说明的对应一节。

## 9. 纳税主体弹窗样板

用这个弹窗作为全站表单的对照实现。业务规则不变，只改呈现。

### 9.1 现在

弹窗约 512px，两列挤在一起。城建税率、申报周期、小微资格下面各有一段说明。小微资格的选项把三项法定条件写进选项文本。说明里的 `**` 原样显示。右上角只有关闭。

### 9.2 改后结构

宽度 720px。标题行：

```text
新建纳税主体                              （说明）   ×
```

正文三个分区，分区标题 13px，分区之间 20px。

**基本信息**

| 字段 | 控件 | 备注 |

### 9.3 右上角说明里要写的内容

标题：纳税主体怎么影响计税

分节，每节先结果后原因：

1. **纳税人类型**  
   决定销项和进项能选哪些税率。一般纳税人与小规模纳税人的档位不同，切换类型后税率会回到该类型的默认档。

2. **城建税率**  
   留空不是 0。增值税底稿的附加税会拒绝出数，避免把未配置当成免税。市区一般填 7，县镇 5，其他 1。

3. **申报周期**  
   只影响小规模纳税人的附加税免征额度：按月 10 万，按季 30 万。未确认时不做免征，可能多缴，不会少缴。一般纳税人可以保持未确认。

4. **小型微利企业**  
   企业所得税在所得额不超过 300 万、从业人数不超过 300、资产总额不超过 5000 万时，实际税负为 5%，否则 25%。三项要同时满足。系统没有从业人数和资产总额，不能自动判定，需要人工选择。未确认按不符合处理。已经选择符合、但所得额超过 300 万时，系统仍按 25% 计算。

说明里不用星号做强调。需要强调的词用次一级标题或单独成句。

## 11. 文案

- 按钮用动词，两个到六个字：保存、提交审批、确认底稿。不用「确定」作为会改数据的按钮。
- 字段名不带括号教程。括号里的口径移到说明。允许保留单位：`城建税率（%）`。
- 选项不超过 8 个字。超过的拆成短标签，解释放说明。
- 状态句不超过 22 个字。
- 错误句说明怎么改：「编码只能使用字母和数字」，不说「校验失败」。
- 禁止在界面字符串里使用 `**`、`#`、反引号。强调靠分节和字重。
- 金额、税额、税率的句子写结果：「按 25% 计税，可能多缴。」不写内部字段名。

## 12. 反馈

| 事件 | 呈现 |
|---|---|
| 保存成功 | 右上角短暂提示，3 秒，一行 |
| 保存失败 | 同一位置，保留到用户关闭；字段错误同时出现在字段下 |
| 不能继续 | 页面标题下一条提示条，带一个去处理的文字按钮 |
| 危险操作 | 确认框，正文点名对象和不可撤销的后果 |
| 后台仍在进行 | 按钮变为进行中并禁用，不用整页遮罩 |

提示条同一页最多一条。成功和失败不占用提示条。

空、加载、失败三种状态全站同一组件：加载用表格骨架；失败给原因和「重试」；空态给一句原因和一个主操作。

## 13. 响应式与键盘

- 设计宽度以 1440 为准，必须同时在 1280 可用。
- 小于 1280：侧栏收起；标准表单弹窗改为全屏抽屉；单据页的右侧信息落到表单下。
- 小于 768：表格改为每行一张摘要卡，保留编号、名称、金额、状态和「更多」。这是后续阶段，第一期保证 1280。
- 所有说明标记、主按钮、关闭按钮可用键盘到达。焦点环 2px 主色，不依赖颜色作为唯一状态。
- 弹窗打开时焦点进入标题，关闭后回到触发它的按钮。

## 14. 验收

用纳税主体弹窗做第一张验收图，通过后再铺到其他页。

弹窗通过条件：

- 右上角是「说明」然后才是关闭。
- 城建税率、申报周期、小微资格下方没有段落说明。
- 三个下拉的选项都是短标签。
- 小微资格停在「未确认」时，字段下只有一句「按 25% 计税，可能多缴。」
- 打开说明能读到四节口径，且看不到 `**`。
- 保存、取消在底部右侧，按钮上没有标记。
- 720px 宽度下两列对齐，底部按钮不随正文滚走。

全站通过条件：

- 抽查合同、项目、发票、税务申报、年结、数据资产：字段标签旁没有 `i`。
- 上述页面中，需要解释的按钮只在自己的右上角有标记，页面另有一个右上角说明。
- 任一页同时可见的提示条不超过一条。
- 1280 宽度下，合同、项目、资产、应收四张表的编号、名称、金额或状态、操作列同时可见。
- 行内可见按钮不超过两个。
- 抽查 10 个弹窗，宽度只使用 420、560、720、880 四档。

## 15. 实施顺序

仍不在本文写代码。确认本需求后按这个顺序改，避免先换颜色、后发现帮助位置又要重排。

1. 做出两个帮助容器：页面/弹窗右上角说明，按钮右上角标记。纳税主体弹窗按第 9 节改完并验收。
2. 去掉全站字段旁 `FieldHelp` 和操作组末尾的独立 `?`，把原文案迁入对应页面的说明。迁的时候删掉 `**`，并改成「先结果、后原因」。
3. 列表模板统一：标题行、筛选行、表格外框、行内两个操作。先改合同、项目、发票、资产，这四页列裁切最明显。
4. 单据页统一吸底操作条。复杂表单从过宽内容的弹窗改为独立页面。
5. 报表和账簿补冻结首列、滚动提示、单元格「—」的一句原因。
6. 最后收字号、间距、空态，使剩余页面与第 6、7 节一致。
