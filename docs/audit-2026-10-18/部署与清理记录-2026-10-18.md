未提供云主机/域名，因此本次为**本机 Docker 部署**，不是公网生产发布。

```bash
cd code

```

结果：

| 容器 | 镜像 | 端口 | 状态 |
|---|---|---|---|
| `code-app-1` | `code-app` | `0.0.0.0:3000 -> 3000` | healthy |
| `code-postgres-1` | `postgres:16` | `127.0.0.1:5434 -> 5432` | healthy |

本机测试入口：

- 本机：<http://127.0.0.1:3000/>
- 局域网：<http://192.168.1.188:3000/>（需 Windows 防火墙放行 3000；手机/同事同一 WLAN）
- 健康检查：<http://127.0.0.1:3000/api/health>
- 管理员账号：`admin`，密码为 `code/.env` 的 `BOOTSTRAP_ADMIN_PASSWORD`（首次初始化时写入容器数据库；不在文档/对话中明文）
- 本地 HTTP 已在 `.env` 设 `COOKIE_SECURE=false`；**生产 HTTPS 必须删除该覆盖**，否则会话 Cookie 不带 Secure。
- 首次登录会要求绑定 MFA（admin 角色强制）：登录页输入密码后显示「绑定双因素认证」，把页面上的密钥手动录入认证器（Google Authenticator / 飞书等），再输入 6 位动态码；确认后会被登出，重新登录并输入动态码。
- 如果仍看到「请先完成 MFA 绑定后再使用系统」，说明浏览器还带着旧的受限 Cookie：访问 `/login` 重新登录即可覆盖；必要时清 Cookie。

验证：

- `GET http://127.0.0.1:3000/api/health` → **200**
- 初始管理员 `admin` 登录 → **201**
- `ENABLE_SCHEDULER=true` 下全部定时任务注册成功（含 `retention_daily` 的两个 handler，job 名分别为 `retention_daily:purgeExpiredChallenges`、`retention_daily:runRetention`）
- 修复了部署时发现的启动崩溃：同一 trigger 多 handler 共用 SchedulerRegistry job 名会抛 `Cron Job ... already exists`

当前部署使用的 `docker-compose.yml` 默认：

- Postgres 宿主端口 `5434`（可 `POSTGRES_HOST_PORT` 覆盖；避免 Windows 5432 端口排除/本地 dev 5433 冲突）
- `TRUST_PROXY_HOPS=0`（直接暴露 3000）；Nginx/SLB 前置时在宿主环境设 1
