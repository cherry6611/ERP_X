# 晟笙 ERP 前端 UI 重设计方案 v2

> 状态：方案稿，未开始改代码  
> 日期：2026-10-19  
> 范围：全站 34 个路由的壳层、列表、详情、表单、报表、后台管理、公共弹窗与提示体系  
> 方向：从“卡片堆叠的后台”改为“安静、数据优先、提示分层的工作台”

---

## 0. 结论先行

### 0.1 提示不要全部改成弹窗

不建议把页面里的提示全部搬进弹窗。

弹窗适合：**短、必须立刻处理、处理完就消失**的内容。  
页面提示适合：**持续存在、边看边操作、不处理就不能继续**的内容。

把所有说明、状态、风险都做成弹窗，会有三个问题：

1. **打断工作**：用户只是想看列表，却被弹窗挡住；
2. **重复打扰**：同一提示每次进页面都弹一次，很快变成“看到就关”；
3. **弹窗变成第二张页面**：内容一多，弹窗里再放卡片、表格、说明，既不好看也不好用。

### 0.2 推荐方案：提示分层，而不是提示弹窗化

| 提示类型 | 放在哪里 | 例子 |
|---|---|---|
| 阻塞性前置条件 | 页面顶部一条**紧凑 NoticeBar** | 未创建纳税主体、未设置会计期间 |
| 操作成功/失败 | **Toast**（右下或右上） | 保存成功、同步完成 |
| 字段解释/口径说明 | **Popover**（问号图标） | 税率、信用额度、预算口径 |
| 记录详情/附件/审计 | **右侧 Drawer** | 合同详情、凭证详情、操作日志 |
| 短确认/短表单 | **Dialog** | 删除确认、3~6 个字段的快速新建 |
| 复杂新建/编辑 | **独立页面 + 吸底操作栏** | 合同登记、项目立项 |
| 全局通知 | **铃铛 Drawer** | 逾期、预警、待办 |
| 首次配置/引导 | **一次性 Setup Drawer** | 初始化清单 |

一句话：**页面负责工作，浮层负责上下文。**

### 0.3 整体视觉方向

**Quiet Ledger / 安静的账本**

- 低饱和、细边框、少投影
- 一个主色：`#3D5AFE`
- 大面积留白，但信息密度不低
- 页面用“区块 + 细线”组织，不用一层层卡片
- 列表是主角，详情用右侧上下文栏，表单像一张文档
- 动效只用于层级变化，不做装饰性漂浮

## 1. 现状审计

### 1.1 量化结果

基于当前源码扫描：

- 34 个路由页面
- `PageShell description=` 58 处
- `text-xs/text-sm text-muted-foreground` 辅助说明 212 处
- 页面级 `TaxEntityBanner / UnassignedEntityVoucherBanner` 引用 10 处
- `<Dialog>` 使用 148 处
- `<Sheet>/<Drawer>` 使用 26 处

结论不是“弹窗太少”，而是**提示没有分层**：该在页面里的、该在字段旁的、该在抽屉里的、该 toast 的，都混在页面正文里。

### 1.2 主要问题

#### A. 页面顶部提示过多

客户、合同、开票等页面顶部会同时出现：

- 页面说明
- 纳税主体提示条
- 操作按钮
- 筛选条

用户进入页面后，第一眼看到的是“说明”，不是“数据”。

#### B. 提示重复

同一个规则会在多个位置重复：

- 页面 description
- 提示条
- 表单 hint
- 弹窗说明
- 错误信息

例如“先创建纳税主体”在客户、合同、开票三处重复出现。

#### C. 弹窗承担了太多内容

部分详情/编辑使用 `Dialog asPage`，内容超过一屏：

- 弹窗里放摘要、表格、附件、操作按钮
- 用户滚动弹窗时看不到页面上下文
- 关闭后忘记刚才看到哪条记录

#### D. 卡片层级过深

- 页面卡片里再套卡片
- 统计卡、筛选卡、表格卡、空态卡层层包裹
- 视觉上“到处是框”，但信息优先级不清楚

#### E. 详情页缺少上下文栏

详情页大多是把字段平铺，缺少：

- 右侧状态/关联/附件/活动
- 当前记录的关键动作
- 与列表的连续感

#### F. 表单像“弹窗放大版”

- 字段从左上到右下排布，缺少分组
- 说明文字堆在表单顶部
- 保存按钮在表单底部，长表单需要滚到底
- 没有“必填/选填/口径”的就近帮助

#### G. 报表筛选重复

财务报表、账簿、税务等页面存在多层筛选：

- 页面顶部一层
- Tab 内再一层
- 表格上方再一层

用户不知道哪一层是“主筛选”。

### 1.3 值得保留的部分

- 现有 7 组 + 底部系统工具的 IA 方向正确
- 表格作为 ERP 主视图是正确的
- 蓝色主色、白色侧栏、浅灰背景的方向正确
- 已有 `PageShell / FilterBar / StatCard / DataState` 可以作为 v2 的基础

v2 不是推翻重来，而是**把已有方向做得更彻底**。

## 2. 设计原则

### 2.1 一屏一个主任务

每个页面只回答一个问题：

- 列表页：我现在要处理哪条记录？
- 详情页：这条记录现在是什么状态？下一步做什么？
- 表单页：我需要填哪几项？
- 报表页：这个期间的数据是否正常？

### 2.2 提示按“是否需要持续可见”分层

- 持续可见 → 页面内
- 需要时再看 → Popover
- 看完就完成 → Toast
- 需要保持列表上下文 → Drawer
- 必须做选择 → Dialog

### 2.3 一个页面最多一条页面级提示

同一页面不允许同时出现两条以上黄色/红色提示条。

多条规则合并成一条“需要处理”的摘要，点开再看详情。

### 2.4 卡片只用于“可重复对象”

卡片用于：

- 指标
- 记录摘要
- 附件
- 空态

不用于：

- 页面分区
- 筛选条
- 表格外壳
- 页面主容器

页面分区用细线和留白，不用卡片套卡片。

### 2.5 文字层级少而稳定

只保留四层：

- 页面标题 24/32
- 区块标题 14/22
- 正文 13/20
- 辅助 11/16

不再出现 15、16、17、18、22 混用。

### 3.1 布局

```text
┌──────────────┬──────────────────────────────────────────────┐
│ Sidebar 232  │ Topbar 60                                    │
│              ├──────────────────────────────────────────────┤
│ 工作台       │ 面包屑 / 页面标题 / 状态 / 主操作             │
│ 客户与合同   │ 可选一行 meta                                 │
│ 项目交付     │ ┌─ 工具条 ────────────────────────────────┐ │
│ 采购与资产   │ │ 搜索 / 筛选 / 视图 / 导出               │ │
│ 财务         │ └─────────────────────────────────────────┘ │
│ 人力与行政   │ 表格 / 内容区                                │
│ 企业文档     │                                              │
│              │                                              │
│ 系统（折叠） │                                              │

```

- Sidebar：232px；折叠 68px
- Topbar：60px
- 内容最大宽度：1480px
- 页面左右 padding：32px
- 区块间距：20px
- 表格行高：52px（舒适）
- 页面背景：`#F6F7F9`
- 内容面：`#FFFFFF`

### 3.2 色彩

| Token | 值 | 用途 |
|---|---|---|
| primary | `#3D5AFE` | 主按钮、选中、链接 |
| primary-soft | `#EEF1FF` | 选中底、图标底 |
| background | `#F6F7F9` | 页面背景 |
| surface | `#FFFFFF` | 表格、表单、弹窗 |
| border | `#E7E9EF` | 细边框 |
| border-strong | `#D8DCE6` | 输入框/分隔 |
| text | `#171A20` | 主文字 |
| text-secondary | `#5F6673` | 次要文字 |
| text-muted | `#8A91A0` | 辅助文字 |
| success | `#1F9D6A` | 通过、已同步 |
| warning | `#C47A12` | 待处理、风险 |
| danger | `#D14343` | 失败、删除 |

规则：

- 主色只用于“可操作”和“当前选中”
- 状态色只用于状态，不用于装饰
- 不使用大面积渐变
- 不使用彩色投影

### 3.3 字体

- 页面标题：24px / 32px / 600
- 页面副标题：13px / 20px / 400
- 区块标题：14px / 22px / 600
- 表格正文：13px / 20px
- 表格表头：11px / 16px / 500，字距 0.04em
- 辅助说明：11px / 16px
- 数字：等宽字体，金额右对齐

### 3.4 圆角/投影

- 输入框/按钮：8px
- 卡片/表格容器：12px
- 弹窗：16px
- 抽屉：16px（左侧直角）
- 投影：只用于浮层；内容面默认无投影

### 3.5 图标

- Lucide，线宽 1.75
- 导航 16px
- 按钮 16px
- 状态 14px
- 不混用填充图标和线性图标

## 5. 提示与浮层体系（核心）

### 5.1 决策矩阵

| 场景 | 组件 | 位置 | 是否阻塞 | 生命周期 |
|---|---|---|---|---|
| 未建纳税主体 | NoticeBar | 页面标题下 | 否 | 条件消失 |
| 未选会计期间 | NoticeBar | 筛选条上方 | 否 | 条件消失 |
| 表单校验失败 | 字段错误 + toast | 字段旁/右上 | 否 | 修正后消失 |
| 保存成功 | Toast | 右上 | 否 | 3 秒 |
| 删除确认 | AlertDialog | 居中 | 是 | 操作完成 |
| 快速新建（≤6 字段） | Dialog | 居中 | 是 | 保存/取消 |
| 复杂新建/编辑 | 独立页 | 全页 | 否 | 路由 |
| 记录详情 | Drawer | 右侧 640 | 否 | 关闭 |
| 附件/审计 | Drawer Tab | 右侧 640 | 否 | 关闭 |
| 口径解释 | Popover | 字段问号旁 | 否 | 点开 |
| 首次配置 | Setup Drawer | 右侧 480 | 否 | 完成/跳过 |
| 批量导入预览 | Dialog 800 | 居中 | 是 | 导入完成 |
| 全局通知 | Drawer | 右侧 420 | 否 | 关闭 |

### 5.2 什么时候用弹窗

推荐用 Dialog：

- 删除/作废/终止确认
- 3~6 个字段的快速新建
- 单条记录选择器
- 批量导入预览
- 需要用户立即做决定的短流程

不推荐用 Dialog：

- 超过 7 个字段的表单
- 需要滚动的详情
- 长期存在的规则说明
- 需要边看列表边对照的内容
- 多层嵌套的表格/卡片

### 5.3 什么时候用 Drawer

推荐用右侧 Drawer：

- 表格行“查看详情”
- 合同/项目/凭证/发票详情
- 附件、审批记录、操作日志
- 通知中心
- 报表行的科目明细
- 快速编辑（≤6 字段），保存后回列表

Drawer 规格：

- 常规：480px
- 详情：640px
- 复杂详情：800px
- 移动端：100%
- 顶部固定标题 + 关闭
- 底部固定操作栏（保存/取消）
- 内容区独立滚动

### 5.4 什么时候用页面

独立页面用于：

- 合同登记
- 项目立项/编辑
- 发票登记
- 多步骤流程
- 需要附件、条款、明细的长表单

页面表单改为“文档式表单”：

```text
┌─────────────────────────────────────────────┬──────────────┐
│ 基本信息                                     │ 填写提示      │
│ 合同名称 [________________________]          │ · 税率口径    │
│ 客户     [________________________]          │ · 附件要求    │
│ 金额     [________________________]          │              │
│                                             │ 当前状态      │
│ 履约信息                                     │ 草稿          │
│ ...                                         │              │
├─────────────────────────────────────────────┴──────────────┤
│ [取消]                                          [保存草稿] [提交] │
└────────────────────────────────────────────────────────────┘
```

- 主表单 2/3 宽，右侧上下文栏 1/3
- 右侧放：填写提示、口径、关联记录、附件
- 底部吸底操作栏，始终可见
- 页面标题不写长说明，说明放到右侧 help

### 5.5 提示文案规范

- 页面 description：最多 28 个汉字，只写“这是什么”
- NoticeBar：最多 2 行，必须带一个动作按钮
- 字段 hint：最多 2 行，放在问号 Popover 里
- Toast：最多 20 个汉字
- 空态：一句说明 + 一个主操作
- 错误：说明 + 下一步，不只写“失败”

示例：

```text
差：请先在纳税主体管理中创建主体。草稿可以先保存，提交审批和开票前必须至少有一个启用主体。
好：还没有纳税主体。提交审批前需要先创建。 [去创建]
```

### 5.6 页面提示收敛规则

1. 同一规则只在一个层级出现。
2. 页面级提示最多一条。
3. 表单 hint 移入字段 Popover。
4. 成功提示一律 toast，不写页面横幅。
5. 风险扫描结果放 Drawer，页面只留一个风险摘要 chip。
6. 通知中心从看板移到铃铛 Drawer。
7. 首次配置用 Setup Drawer，不在每个页面重复提示。

## 6. 页面模板

### 6.1 列表页

```text
面包屑
页面标题 + 数量 + 状态 + 主操作
[可选一条 NoticeBar]
工具栏：搜索 / 筛选 / 视图 / 导出 / 列设置
表格
分页
```

规则：

- 表格直接放在内容面上，不再套一层卡片
- 工具栏与表格同宽
- 主操作只保留一个
- 次级操作收进“更多”
- 空态只显示一句 + 一个动作
- 批量选择后出现底部浮动操作条

### 6.2 详情页

```text
面包屑
标题 + 状态 + 操作
摘要条：4~6 个关键字段
Tab：概览 / 明细 / 附件 / 变更 / 日志
主内容 2/3 + 右侧上下文 1/3
```

右侧上下文栏：

- 当前状态
- 关联记录
- 负责人
- 附件
- 最近操作

详情页不再用 Dialog 承载。

### 6.3 表单页

- 文档式分区
- 标签左对齐或顶部对齐二选一，全站统一
- 必填标记在 label 后
- 字段帮助用问号 Popover
- 底部吸底操作栏
- 离开未保存提示用 Dialog

### 6.4 报表页

```text
标题 + 期间 + 主体 + 导出
口径摘要（一行）
校验 chip（通过/差异）
报表主表 / 图表
```

- 筛选只保留一层
- 口径说明用 Popover
- 校验差异用 chip + Drawer
- 报表纸张感：白底、细线、数字右对齐

### 6.5 设置页

- 左侧二级导航
- 右侧内容最大 880px
- 每个设置组一张卡，不再全宽堆叠
- 保存按钮吸底或组内保存

### 6.6 看板

- 第一行 4 个指标
- 第二行趋势 2/3 + 待办 1/3
- 待办列表最多 5 条，更多进 Drawer
- 不再放“说明型”卡片
