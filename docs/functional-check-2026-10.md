## 五、发现的问题（2 项，均低风险）

| # | 问题 | 影响 | 修复建议 |
|---|------|------|---------|
| P1 | `GET /api/attachments` 裸调（缺 sourceType/sourceId 参数）返回 500 | 前端调用总带参数，页面不受影响；仅健壮性缺陷（应为 400） | controller 层对必填 query 参数加显式校验，缺参抛 `BadRequestException` |
| P2 | 付款审批端点 `action` 缺省时默认走 reject 分支 | 前端总是显式传值，功能不受影响；但空 action 被解释为「驳回」语义不安全 | DTO 加 `@IsIn(['approve','reject'])` 必填校验 |

未发现：路由 404、前后端 method/path 不匹配、悬空 import、占位页残留、状态机漏洞、核销金额错配、BI 汇总与明细不一致等问题。

## 六、上线运行建议

1. **上线前待办**
   - （可选，建议）修复 P1/P2 两个健壮性缺陷，工作量极小。
   - 在插件配置页为 3 个 feishu-bitable 实例填写 appToken / tableID：`erp_bitable_two_way_sync_1`（成本出向）、`contract_ledger_archiving_1`（合同出向）、`flexible_labor_hours_sync_1`（工时入向）；填好后激活触发器 `feishu_daily_sync`。当前未配置属「降级运行」，同步链路不生效。
   - 确认审批通知插件实例 `send_erp_approval_notification_1` 收件人配置（提交人+admin）符合预期。

2. **发布后复核（运行态）**
   - 复核两个已激活 cron 触发器（admin_rent_expiry_remind、customer_credit_alert）的真实触发效果：开发态审计日志显示其 09:16 触发但 `__innerapi__/automation/invoke` 返回 404——这是**应用未发布期间的环境限制**（cron 调度经平台网关转发，本地 dev 环境无此路由），发布后需在运行态通过审计日志确认实际执行结果。
   - 观察首日 BI 看板与审计日志的量级是否正常。

3. **运行期注意事项**
   - 数据库为单环境配置（开发/生产共享）：正式启用前建议确认数据隔离策略，生产库不保留演示数据（本项目测试数据均已清理留档）。
   - 定期查看 `/api/bi/alerts` 与客户信用预警 cron 的送达情况；超 80% 额度预警逻辑此前已按 SQL 级验证。
   - 飞书同步链路（feishu-sync 模块）依赖幂等映射表 `comp_feishu_sync_record`，首次启用后建议核对同步记录数与源数据量。

4. **已知环境限制（非缺陷）**
   - E2E/沙箱浏览器链路为匿名身份，RLS 拒绝写操作属预期防线；写链路以接口级实测为准。
   - CanRole 包裹的管理按钮在浏览器侧角色接口不可达时隐藏，等价于「普通员工视角」；后端 @CanRole 鉴权独立生效，已由接口级测试证实。
